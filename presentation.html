KKU Security Scorecard & Vulnerability Management Dashboard

01. Overview
ทำอะไร (What is it?)
KKU Security Scorecard คือ แดชบอร์ดประเมินความปลอดภัยไซเบอร์แบบ Full-stack รวบรวมข้อมูลสถานะช่องโหว่ความเสี่ยงของทุกคณะในมหาวิทยาลัยขอนแก่น
  • Security Rating: ประเมินระบบเครือข่าย โดเมน และเว็บไซต์ โดยตัดเกรด A-F เพื่อให้เห็นภาพระดับความปลอดภัยที่เข้าใจง่าย
  • Centralized Database: จัดเก็บข้อมูลจาก API และ CSV Import วิเคราะห์ประวัติย้อนหลังและแนวโน้มความเสี่ยง
  • Interactive Map: แสดงพิกัดที่ตั้งคณะย่อยและปักหมุดสีตามเกรดความปลอดภัยเพื่อชี้เป้าจุดอ่อนได้ทันที
02. Motivation
ทำไมถึงทำ (Why did we do it?)
  • โครงข่ายขนาดใหญ่: มหาวิทยาลัยขอนแก่นมีคณะและหน่วยงานย่อยมากกว่า 21 แห่ง ซึ่งแต่ละแห่งบริหารจัดการระบบเซิร์ฟเวอร์และเครือข่ายของตนเอง
  • ความเสี่ยงรอบด้าน: เผชิญกับภัยคุกคาม เช่น การละเลยการอัปเดตระบบ (Patching), โดเมนหลอกลวง, DNS Spoofing และช่องโหว่บนแอปพลิเคชันเว็บ
  • ขาดภาพรวม (No Visibility): เดิมทีไม่มีระบบแดชบอร์ดที่รวมข้อมูลประเมินคะแนนของทุกหน่วยงาน ทำให้ผู้บริหารและศูนย์คอมพิวเตอร์ขาดข้อมูลภาพรวม
  • ประสานงานล่าช้า: เมื่อพบช่องโหว่ความเสี่ยง การชี้เป้าหาผู้รับผิดชอบและอุปกรณ์ที่เจาะจงทำได้ยากและใช้เวลานาน

ภัยคุกคามไซเบอร์และช่องทางรั่วไหล

หากหน่วยงานย่อยเพียงจุดเดียวมีช่องโหว่ อาจกลายเป็นประตูทางเข้า (Entry Point) ให้ผู้ไม่ประสงค์ดีโจมตีเครือข่ายหลักทั้งหมดของมหาวิทยาลัยได้

* ปัญหาหลัก: ขาด Single Source of Truth
03. Solution
แก้ปัญหาอย่างไร (How we solve it)
  • ดึงข้อมูลอัตโนมัติและแมนนวล: เชื่อมต่อตรงกับ SecurityScorecard API เพื่อตรวจข้อมูลสด และรองรับการอัปโหลดข้อมูลจากไฟล์ภายนอก (CSV Upload)
  • แมปปิ้งโดเมนอัจฉริยะ: พัฒนาอัลกอริทึมวิเคราะห์โดเมนและไอพีของโฮสต์ที่มีความเสี่ยง แล้วคัดกรองจัดกลุ่มเข้าสู่คณะที่รับผิดชอบโดยอัตโนมัติ
  • แสดงผลเชิงตำแหน่ง: แผนที่วิทยาเขต (Leaflet Map) แสดงผลหมุดโลโก้คณะและเปลี่ยนสีหมุดตามเกรดความปลอดภัย ช่วยให้เจาะลึกพื้นที่และคณะที่มีช่องโหว่ได้อย่างทันที
04. Technology
ทำอย่างไร (How did we do it?)

สถาปัตยกรรมระบบ (Full-stack Monorepo)

พัฒนาและจำลองสภาพแวดล้อมเครือข่ายด้วย Docker-compose เพื่อความเสถียรและแยกการประมวลผลออกเป็นบริการย่อย (Services)

  • Frontend: พัฒนาโดย Next.js แสดงแผนที่โต้ตอบด้วย Leaflet.js และกราฟความเสี่ยงในรูปแบบ Light Mode
  • Backend: พัฒนาโดย Express (Node.js) พร้อม Prisma Client เชื่อมต่อ PostgreSQL
  • Data Processor: สคริปต์ Python วิเคราะห์ คัดกรองข้อมูล และแปลงพิกัด
  • Security Engine: เข้ารหัสคีย์และข้อมูลความลับของระบบด้วย AES-256-GCM
05. Outcomes
ผลลัพธ์เป็นอย่างไร (Results)
  • ระบบติดตามศูนย์กลาง (Centralized Dashboard): ฝ่ายไอทีส่วนกลางสามารถมองเห็นคะแนนสุขภาพความปลอดภัยของมหาวิทยาลัยได้ครอบคลุมแบบ 360 องศา
  • วิเคราะห์ชี้เป้าแม่นยำ: ทราบพิกัดและโดเมนของเซิร์ฟเวอร์ที่มีช่องโหว่ความเสี่ยง โดยไม่ต้องเสียเวลาค้นหาแยกส่วน
  • ความตระหนักร่วมกัน: แต่ละคณะเห็นระดับความปลอดภัยของตนเองผ่านระบบเกรด ช่วยกระตุ้นให้เกิดการตื่นตัวและประสานงานแก้ไขได้เร็วขึ้น
